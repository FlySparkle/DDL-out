# ADR 005：对称配对与大文件同步传输

## 状态

于 2026-08-10 采纳。

协议版本与配对密钥前缀后来因可选截止时间变更为 6 和 `DDL6:`，见
[ADR 006](006-optional-task-deadlines.md)。其余决策仍然有效。

## 决策

- 不再按电脑与手机固定同步角色。任意设备都可发起同步，发起方生成两分钟有效的二维码和可复制的一次性配对密钥；接收方可扫码或粘贴密钥。
- 二维码与文本密钥编码同一份会话信息，使用 `DDL5:` 前缀和 Base64URL；会话仍通过 256 位随机密钥与 AES-GCM 加密。
- 发起方默认负责冲突审批，角色与平台无关。
- 标准模式保留单项 256 MiB 安全上限。双方均开启“大文件传输”后，不设置应用层总大小或单项大小上限。
- 大文件模式使用 512 KiB 固定分块、逐块确认形成背压，并对每项数据做 SHA-256 校验。超过 8 MiB 的待传输或接收数据先暂存系统临时文件，会话结束后清理。
- 冲突界面不得展示内部哈希、同步 UUID、排序键或原始结构化字段。文本冲突显示可读文本，图片冲突显示文件名，排序冲突只显示冲突类型与设备名。

## 影响

大文件模式消除了应用自身的传输大小限制，但实际可传输容量仍受两端可用存储、内存、操作系统和局域网稳定性约束。协议版本提升到 5，旧协议会话需要由新版本重新发起。
